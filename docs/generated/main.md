# Разбор src/main.cpp (композиция и главный цикл)

## Назначение

`src/main.cpp` — точка входа и **composition root**: собирает конкретные реализации модулей (по флагам сборки), регистрирует параметры в реестре, задаёт начальные значения и исполняет неблокирующий главный цикл с фиксированным порядком шагов. Планируемые изменения — раздел 7 [base-design.md](../sessions/base/artifacts/base-design.md) (строки главного цикла, расписания полинга).

## Файлы

## setup() — инициализация

Планируемые шаги (по требованиям и текущей структуре; текущий вариант — справочно, из кода: [src/main.cpp](../../src/main.cpp:59)):

1. Запуск Serial (отладка/симулятор, 9600) и Serial1 (DWIN, 115200) при отсутствии симулятора DWIN.
2. Регистрация адресов в `parameter_registry` (дескрипторы: категория, масштаб, единица, потребитель) — целевой контракт [module-router-registry.md](./module-router-registry.md).
3. Привязка хранилищ к трансляторам (привязка `parameter_storage → parameter_translator`).
4. **Значения по умолчанию**: скорость привода `0x6000` = 60 об/мин и масштаб `0x6002` = 10000 (справочно, из кода: [src/main.cpp](../../src/main.cpp:74)); целевые уставки дефолтов уточняются на этапе разработки (R-3).
5. **Включение привода**: `servo_impl.enable()` — один раз при старте (целевой контракт драйвера; справочно, из кода: [src/main.cpp](../../src/main.cpp:77)).
6. Диагностическое сообщение о готовности и (в режиме симулятора) подсказка по формату команд.

## loop() — главный цикл

Целевой порядок шагов фиксирован и выражает приоритеты (дизайн, раздел 3; FR-15..FR-17):

1. **Опрос источника данных** (`data_source`): полинг RAM DWIN по расписанию `millis()`; приём байт из кольцевого буфера (FR-2).
2. **Разбор кадров DWIN** в события «адрес, значение» (без ожиданий; FR-1).
3. **Обработка параметров системы (приоритет 1)**: каждое событие угла сразу пишется в хранилище и передаётся транслятору движения; новая цель применяется немедленно (FR-9).
4. **Обработка настроек (приоритет 2)**: только если в этом проходе не было свежих системных параметров; квота — не чаще раза в N проходов (N = 10–20; FR-16, R-5).
5. **Тик трансляторов** (`tick()`): конечный автомат движения, таймауты по `millis()`.
6. **Тик драйверов** (`tick()`): RS485 — переключение RSE, отправка команды из очереди, ожидание ответа с таймаутом.
7. **Периодическая диагностика** в Serial (9600).

Ни одна операция не блокируется: **нет `delay()`**, нет ожидания UART/RS485 (FR-17, AC-3). Задержка «приём системного параметра → команда драйверу» — не более одного прохода цикла (NFR-1).

Периодичность полинга (дизайн, раздел 3): системные адреса — каждый цикл (или 10–20 мс); настройки — редкий период (200–500 мс). Текущий код содержит черновой вариант полинга с периодом 200 мс по всем адресам (справочно, из кода: [src/main.cpp](../../src/main.cpp:91)) — целевое расписание уточняется по R-2.

## Принципы (из артефактов аналитика)

- **Неблокирующий главный цикл** (раздел 10, п.4): тики вместо ожиданий; `millis()` всегда растёт (NFR-4, AC-3).
- **Приоритеты + квота** (раздел 10, п.3): пункты 3–4 цикла.
- **Композиция на этапе сборки** (раздел 2 [README.md](../../README.md)): замена дисплея/драйвера/транспорта — без изменения логики.
