# Модули: parameter_router и parameter_registry (маршрутизация обновлений)

## Назначение

`parameter_router` — входная точка главного цикла: принимает события от `data_source`, через `parameter_registry` определяет категорию и пишет значение в `parameter_storage`, применяя **приоритет обработки** System → Setting. `parameter_registry` — статический **каталог описаний** параметров (адрес, категория, масштаб, единица, потребитель); **значений не хранит** (дизайн, раздел 1).

## Файлы

- `include/parameter_router.h` + `src/parameter_router.cpp` — диспетчер событий (планируемые изменения по разделу 7 дизайна).
- `include/parameter_registry.h` + `src/parameter_registry.cpp` — каталог дескрипторов.
- `include/parameter_addresses.h` — константы адресов (см. [module-addresses.md](./module-addresses.md)).

## Поведение

### Маршрутизация по адресу

1. Событие `parameter_update{address, raw}` от `data_source` (FR-1..FR-2).
2. Роутер ищет дескриптор в реестре: `find(address)`.
3. **Известный адрес**: по категории дескриптора выбирается порядок обработки:
   - `System` — запись в хранилище и обработка в **том же проходе** главного цикла (FR-15);
   - `Setting` — запись в хранилище с установкой флага «изменилась»; применение откладывается до фазы настроек цикла (FR-8).
4. **Неизвестный адрес**: отбрасывается с технической диагностикой в Serial; цикл не прерывается (FR-5, AC-8; сценарий S6 приёмки).

### Приоритеты и квота настроек

- Два правила (дизайн, раздел 4):
  1. Параметры системы **не встают позади** настроек (`processSystem` первым).
  2. Настройки не могут быть «заморожены» навсегда потоком углов: `processSettings` вызывается **не чаще раза в N проходов** (N = 10–20, R-5) — квота как гарантия (FR-16, AC-6; сценарий S4).
- В штатном режиме угол обновяется раз в минуту (R-5) — квота страховая, не повседневная.
- Планируемая реализация приоритетной фазы цикла — задача T3 [base-tasks.md](../sessions/base/artifacts/base-tasks.md).

### Реестр как точка привязки «адрес → потребитель»

- Каталог — единственная точка связывания «адрес VP → категория → потребитель»; кто потребляет параметр, определяет **запись реестра**, а не роутер и не главный цикл (дизайн, раздел 6).
- Масштаб живёт в дескрипторе (`scale_x1000`), единица и потребитель — тоже; смена масштаба не требует правки транслятора (дизайн, раздел 9, R-3).
- Набор адресов и категорий — раздел 9 [base-design.md](../sessions/base/artifacts/base-design.md), AC-4.

## Принципы (из артефактов аналитика)

- **Источник один, устройств много** (дизайн, раздел 10, п.2): реестр превращает плоскую таблицу адресов в связку «адрес → категория → потребитель»; новые устройства добавляются строками реестра и новыми драйверами без изменения цепочки вызовов.
- **Настройки дешевле системы** (раздел 10, п.3): приоритет System и квота Setting.
- **Ресурсы** (раздел 10, п.5): каталог — статическая таблица компактных типов (uint16_t адрес, uint8_t категория), без `std::map`.
