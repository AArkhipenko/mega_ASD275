# Модуль: driver_interface (драйвер устройства)

## Назначение

Транспортно-зависимая выдача команд устройству (ASD275). Инкапсулирует различия транспорта и модели привода: транслятор работает с **логическими командами движения**, драйвер — с конкретным интерфейсом (RS485 Modbus RTU; в перспективе RS111). Реализации: `servo_driver` (реальный ASD275) и `servo_simulator` (имитация).

## Файлы

- `include/driver_interface.h` — контракт драйвера (целевые изменения по разделу 7 дизайна; существующий заголовок — справочный контекст).
- `lib/servo_driver/*` — `servo_driver`: очередь команд, таймауты, переключение RSE, диагностика (планируемые изменения).
- `lib/servo_simulator/*` — `servo_simulator`: та же семантика команд, что у реального драйвера (NFR-5).

## Поведение

### Очередь команд 1+1 (буфер C, дизайн, раздел 2.3)

- Максимум **2 слота**: команда «в полёте» (выставлена по RS485, ждёт ответа или таймаута) и команда «на очереди».
- Пока команда «в полёте», новые команды **физически не выдаются** — half-duplex RS485 не позволяет передавать до получения ответа.
- При приходе новой команды она **замещает** команду «на очереди» (latest-wins и здесь).
- **Таймаут ответа** — по `millis()`, константа порядка 100–200 мс (в существующем коде 100 мс, справочно: [lib/servo_driver/src/servo_driver.h](../../lib/servo_driver/src/servo_driver.h:42)). По истечении — диагностика ошибки связи, команда снимается, очередь продолжает работать (FR-14).
- **Цель угла никогда не ставится в очередь**: она живёт в хранилище (буфер B); драйвер получает только нормированное текущее действие (дизайн, раздел 2.3).

### RS485 (Modbus RTU)

- Пин RSE = D2 переключается под передачу/приём без блокирующего ожидания (FR-13; справочно, из кода: [lib/servo_driver/src/servo_driver.h](../../lib/servo_driver/src/servo_driver.h:14)).
- Связь: Serial3, 9600 8N2, адрес привода по умолчанию 0x01 (справочно, из кода: [lib/servo_driver/src/servo_driver.h](../../lib/servo_driver/src/servo_driver.h:19)).
- Регистры ASD275 (справочно, из кода: [lib/servo_driver/src/servo_driver.h](../../lib/servo_driver/src/servo_driver.h:29)):

| Регистр | Назначение |
|---|---|
| `0xB5` | Включение привода (enable, один раз при старте) |
| `0x11F` | Старт/сброс движения (подача 1 → 0) |
| `0x202` | Количество оборотов (знак — направление) |
| `0x204` | Скорость вращения, об/мин |
| `0x1000` | Мониторинг: ≠ 0 — привод вращается |

- Последовательность движения: запись 0x202 (обороты) → запись 0x204 (скорость) → 0x11F = 1 → 0.

## Состояние «двигается»

- `is_moving()` опрашивает регистр мониторинга (0x1000): ≠ 0 — движение идёт (README, раздел 3.4).
- Транслятор в `tick()` использует этот статус для завершения движения; при «зависшем» движении — таймаут и аварийная остановка.
- Ошибка связи (нет ответа до таймаута) — диагностическое/аварийное состояние, главный цикл не останавливается (FR-14, AC-7).

## Принципы (из артефактов аналитика)

- **Полудуплекс требует терпения** (дизайн, раздел 10, п.4): одна команда в полёте + таймауты вместо ожидания ответа в цикле.
- **Свежесть данных в очереди** (раздел 10, п.1): замещение команды «на очереди» новейшей.
- **Симуляторы — контракт** (раздел 10, п.6): `servo_simulator` повторяет ту же семантику (приёмка AC-2, AC-9).
- **Модель устройства — в адаптере** (README, раздел 2.5): набор регистров ASD275 учитывается внутри реализации интерфейса, верхняя логика от модели не зависит.

## Связи

- Вызывает: RS485 (Serial3), пин RSE (D2).
- Вызывается из: `parameter_translator` (`sendCommand`), `src/main.cpp::loop()` (`tick()` драйвера), при старте — `enable()` из `setup()`.
