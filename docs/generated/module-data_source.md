# Модуль: data_source (источник данных)

## Назначение

Единственный источник данных системы. Предоставляет события обновления параметра `parameter_update{address, raw_value}` и **не знает** категорий, устройств и потребителей — классификация происходит ниже по цепочке (дизайн, раздел 1). Реализации: реальный DWIN по RS232 и его симулятор через Serial.

## Файлы

- `include/data_source.h` — интерфейс `data_source` и структура события `parameter_update`.
- `lib/dwin_lcm/*` — реализация для реального DWIN (RS232, Serial1, 115200 бод): кольцевой RX-буфер, парсер кадров 0x82/0x83, публикация событий (планируемые изменения по разделу 7 дизайна).
- `lib/dwin_lcm_simulator/*` — симулятор DWIN: тот же интерфейс событий, ввод «адрес значение» из Serial (флаг `USE_DWIN_LCM_SIMULATOR`).

## Поведение

1. **Буфер A** (дизайн, раздел 2.1): программный кольцевой буфер на 128 байт (порядка длины нескольких кадров DWIN) внутри `dwin_lcm`; аппаратный RX-буфер UART — первый уровень. Заполняется обработчиком прерывания UART, главный цикл только читает.
2. **Переполнение**: старые непрочитанные байты перезаписываются (свежие данные важнее старых); при битом кадре парсер сбрасывается на поиск заголовка (устойчивость к мусору на RS232, требования раздел 6).
3. **Парсинг — в главном цикле** (FR-1): кадр разбирается полностью и публикуется как `parameter_update`; если кадр неполон — парсер выходит, ожидания полного кадра в цикле нет.
4. **Периодический полинг RAM DWIN** по расписанию `millis()` (FR-2): системные адреса (0x5002) — часто (каждый цикл или период 10–20 мс), настроечные (0x6000..0x6004) — редко (200–500 мс) (R-2, дизайн раздел 3).
5. **Симулятор** (флаг `USE_DWIN_LCM_SIMULATOR`, [platformio.ini](../../platformio.ini:26)): ввод строк `адрес значение` (например `0x5002 4500`) из Serial; интерфейсная семантика не отличается от реального железа (FR-3, NFR-5).

> Примечание: текущий код ещё не реализует целевую архитектуру буфера A (128 байт, перезапись при переполнении) — в существующем заголовке виден приёмник кадра с фиксированным буфером 32 байта (справочно, из кода: [lib/dwin_lcm/src/dwin_lcm.h](../../lib/dwin_lcm/src/dwin_lcm.h:48)). Планируемые изменения — раздел 7 дизайна.

## Принципы (из артефактов аналитика)

- **Источник всегда один** (дизайн, раздел 10, п.2): DWIN — единая точка входа; источник не знает о потребителях.
- **Свежие данные важнее истории** (раздел 10, п.1): перезапись старых байт при переполнении буфера — следствие этого принципа на уровне приёма.
- **Буфер — десятки байт, не килобайты** (NFR-7, раздел 10, п.5): 128 байт укладывается в бюджет SRAM 8 КБ.

## Связи

- Вызывает: ничего — публикует события для потребителей.
- Вызывается из: `parameter_router` (опрос через `try_read_update` в главном цикле); `src/main.cpp` (периодический полинг RAM DWIN через `read_ram`); композиция — в `main.cpp`.
- Публикует: `parameter_update` → `parameter_router` → `parameter_registry`/`parameter_storage` (см. [flow.md](./flow.md)).
- Планируемая реализация в цепочке: [modules.md](./modules.md).
