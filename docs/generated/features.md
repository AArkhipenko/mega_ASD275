# Функциональность системы

Список возможностей целевой прошивки по разделам [base-requirements.md](../sessions/base/artifacts/base-requirements.md). Так как этап разработки не выполнялся, ссылки на код — планируемые файлы (раздел 7 дизайна) и целевые контракты (раздел 8 [base-design.md](../sessions/base/artifacts/base-design.md)); пометки «(справочно, из кода)» указывают на существующие в текущем коде имена/сигнатуры.

## 1. Категории параметров (System / Setting)

- Каждый VP-адрес представлен в реестре дескриптором: категория, масштаб, единица, потребитель (FR-4).
- `Category { System, Setting }`, `ParameterDescriptor { address, category, scale_x1000, unit, consumer }`, поиск `find(address)` (дизайн, раздел 8).
- Классификация: `0x5002`, `0x5004` → System; `0x6000`, `0x6002`, `0x6004` → Setting (AC-4).
- Планируемый файл: `include/parameter_registry.h`, `include/parameter_addresses.h`.
- Реализация: [module-router-registry.md](./module-router-registry.md), [module-addresses.md](./module-addresses.md).

## 2. Приём уставок (неблокирующий, DWIN)

- Кольцевой RX-буфер 128 байт + парсер в главном цикле, без ожидания полного кадра (FR-1).
- Периодическое чтение RAM DWIN по `millis()`: система — часто (каждый цикл или 10–20 мс), настройки — редко (200–500 мс) (FR-2, R-2).
- Переполнение буфера — перезапись старых байт; битый кадр — сброс парсера на заголовок (дизайн, раздел 2.1; приёмка S7).
- Планируемый файл: `lib/dwin_lcm/*` (+ `lib/dwin_lcm_simulator/*`).
- Реализация: [module-data_source.md](./module-data_source.md).

## 3. Маршрутизация и реестр

- Роутер классифицирует событие через реестр и пишет в хранилище (`handleEvent`), обрабатывает системы (`processSystem`) и настройки (`processSettings`) (дизайн, раздел 8).
- Неизвестный адрес — диагностика и отброс, цикл не прерывается (FR-5, AC-8; сценарий S6).
- Планируемый файл: `include/parameter_router.h`, `include/parameter_registry.h`.
- Реализация: [module-router-registry.md](./module-router-registry.md).

## 4. Хранилище: latest-wins и флаги

- Хранение последнего значения на адрес + флаг «изменился» (FR-6).
- Политика latest-wins для System (FR-7) и для Setting с флагом (FR-8); FIFO целевых целей нет (NFR-3).
- API `write/read/hasChanged/clearChanged` (дизайн, раздел 8).
- Планируемые файлы: `include/parameter_storage.h`, `include/scaled_parameter.h`, `include/axis_settings.h`.
- Реализация: [module-storage.md](./module-storage.md).

## 5. Обработка угла (0x5002) — движение с перенацеливанием

- `delta = target − current` в физических единицах (`raw × масштаб`, масштаб из реестра; FR-11).
- `|delta| < epsilon` → движения нет.
- **Re-targeting**: смена целевого угла во время движения перенацеливает движение немедленно, очереди целей не создаётся (FR-9; AC-5; сценарии S1, S2, S8).
- Масштаб угла 0.01: `0x5002 4500` → 45.00° (AC-10, S8).
- Планируемый файл: `include/axis_motion_translator.h`, `include/parameter_translator.h`.
- Реализация: [module-translator.md](./module-translator.md).

## 6. Скорость (0x6000) — только при старте движения

- Скорость считывается из хранилища в момент старта и включается в команду старта (FR-10).
- Во время движения скорость не меняется и не применяется — ограничение ASD275, риск R-1 закрыт (дизайн, раздел 5; сценарий S3).
- Новая скорость действует при следующем старте движения.
- Планируемые файлы: `include/axis_settings.h` (скорость + масштаб в одном хранилище), `include/axis_motion_translator.h`.
- Реализация: [module-translator.md](./module-translator.md), [module-storage.md](./module-storage.md).

## 7. Приоритеты и квота настроек

- Приоритет 1 — все накопленные параметры системы; приоритет 2 — настройки, если свежих системных в этом проходе не было (FR-15).
- Квота: настройки применяются не чаще раза в N проходов (N = 10–20 как дефолт; R-5) — гарантия, что поток углов не «замораживает» настройки (FR-16; AC-6; сценарий S4).
- Планируемый файл: `src/main.cpp` (порядок шагов цикла).
- Реализация: [main.md](./main.md), [flow.md](./flow.md).

## 8. Драйвер по RS485 (Modbus RTU, ASD275)

- Неблокирующая выдача: очередь максимум «1 в полёте + 1 на очереди», новая команда замещает стоящую (FR-12; AC-7; сценарий S5).
- Ответ — по таймауту `millis()` (порядок 100–200 мс); ошибка связи — диагностика, цикл продолжается (FR-14).
- Пин RSE (D2) без блокирующего переключения (FR-13).
- Регистры ASD275: 0xB5 (enable), 0x11F (старт/сброс), 0x202 (обороты), 0x204 (скорость), 0x1000 (мониторинг) (справочно, из кода: [lib/servo_driver/src/servo_driver.h](../../lib/servo_driver/src/servo_driver.h:29)).
- Планируемый файл: `lib/servo_driver/*`, `include/driver_interface.h`.
- Реализация: [module-driver.md](./module-driver.md).

## 9. Симуляторы

- `USE_DWIN_LCM_SIMULATOR` — ввод «адрес значение» из Serial вместо кадров DWIN (FR-3).
- `USE_SERVO_SIMULATOR` — имитация привода вместо ASD275.
- Та же интерфейсная семантика, что реальные устройства (NFR-5; AC-2, AC-9).
- Флаги: [platformio.ini](../../platformio.ini:26) (строка 28).
- Реализация: [module-data_source.md](./module-data_source.md), [module-driver.md](./module-driver.md), [overview.md](./overview.md).
