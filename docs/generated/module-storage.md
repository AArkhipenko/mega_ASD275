# Модуль: parameter_storage (хранилище значений)

## Назначение

Хранилище — единственное место целевой архитектуры, где значения параметров **живут между проходами главного цикла** (дизайн, раздел 1). В дизайне это статическая таблица записей «адрес → последнее значение + флаг «изменился»» с политикой **latest-wins** (буфер B, раздел 2.2).

## Файлы

- `include/parameter_storage.h` — целевой контракт таблицы значений (раздел 8 дизайна); существующий заголовок содержит более раннюю редакцию интерфейса (объект-хранилище на параметр) — только справочный контекст.
- `include/scaled_parameter.h` — планируемое хранилище параметра с линейным масштабом «сырое → физические единицы» (угол, расстояние).
- `include/axis_settings.h` — планируемое многоадресное хранилище настроек оси (скорость 0x6000 + масштаб 0x6002).
- `src/scaled_parameter.cpp`, `src/axis_settings.cpp` — планируемые реализации.

## Публичное API

### Целевой контракт (дизайн, раздел 8)

| Сигнатура | Описание |
|---|---|
| `bool write(uint16_t address, int32_t raw)` | Запись values с latest-wins; флаг «изменился» = true |
| `bool read(uint16_t address, int32_t& raw) const` | Чтение последнего значения |
| `bool hasChanged(uint16_t address) const` | Проверка флага изменения |
| `void clearChanged(uint16_t address)` | Сброс флага — вызывает потребитель после обработки |

Все записи — O(1) (линейный поиск по небольшой таблице допустим), аллокаций нет (дизайн, раздел 8).

## Поведение

- Одна запись на адрес из реестра: `{адрес uint16_t, значение int32_t raw, флаг uint8_t}` (дизайн, раздел 2.2).
- **latest-wins** (FR-7): новое значение перезаписывает старое безусловно — гарантия, что исполнение не работает с устаревшими целями; FIFO целевых углов нет (NFR-3).
- **Флаг «изменился»** (FR-6, FR-8): устанавливается при записи, сбрасывается потребителем после обработки (`clearChanged`); служит сигналом для применения настроек по квоте.
- Для параметров System обработка происходит в том же проходе цикла (флаг не нужен для исполнения), для Setting — отложенно, по правилам приоритета (FR-15, FR-16).

## Многоадресные хранилища (`owns` / `address_at`)

Настройки, которые задаются вместе и редко изменяются, объединяются в **одно хранилище**, принимающее несколько адресов: `axis_settings` обслуживает VP 0x6000 (скорость) и 0x6002 (оборотов на градус). Соответствие «адрес → хранилище» раскрывается через `owns(address)` и перечисление `address_at(i)`:

- (справочно, из кода) [include/axis_settings.h](../../include/axis_settings.h:25) — `owns` для двух адресов;
- `address_count()` = 2, `address_at(0)` — скорость, `address_at(1)` — масштаб (справочно, из кода: [include/axis_settings.h](../../include/axis_settings.h:28), :31);
- Доступ к значениям: `rpm()` ([include/axis_settings.h](../../include/axis_settings.h:47)) и `revs_per_degree()` (:51).

Транслятор **кэширует** настройки и обновляет кэш только по уведомлению об изменении хранилища (`on_settings_changed`) — настройки не перечитываются и не изменяются при каждом движении (дизайн, раздел 2.3).

## Когда вызывается транслятор

В целевой архитектуре транслятор уведомляется через флаг «изменился» (флаг читает роутер/главный цикл, вызывая обработку системы или настроек), в текущей редакции — напрямую из `apply_update` через привязанный `attach_translator` (справочно, из кода: [include/parameter_storage.h](../../include/parameter_storage.h:24)). Целевые правила вызова — дизайн, разделы 3–4.

## Принципы (из артефактов аналитика)

- **Свежие данные важнее полноты истории** (раздел 10, п.1): хранение только последнего значения вместо очередей целей.
- **Хранилище — единственное место между проходами** (раздел 10): реестр значений не хранит; трансляторы/драйверы состояния не несут (кроме кэшей и очереди драйвера).
- **Ресурсы** (раздел 10, п.5): статический массив, компактные типы; целевой бюджет ~16 байт на запись (NFR-7).

## Связи

- Вызывает: `parameter_translator` (уведомление об изменении — в целевой архитектуре через флаг, обрабатываемый в цикле).
- Вызывается из: `parameter_router` (запись событий), `parameter_translator`/главный цикл (чтение значений и сброс флагов), `src/main.cpp` (инициализация и тики).
- Взаимодействует с: `parameter_registry` (адреса регистрируются, значения хранятся отдельно — дизайн, раздел 1).
