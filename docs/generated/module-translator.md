# Модуль: parameter_translator (преобразователь «параметр → команды»)

## Назначение

Преобразует новое состояние параметра (значение в хранилище) в **набор логических команд движения** для `driver_interface`. Работает в **физических величинах** (физическая = raw × масштаб, масштаб из реестра). Конкретная реализация для оси — `axis_motion_translator`: дельта параметра → обороты/направление/скорость + контроль завершения движения.

## Файлы

- `include/parameter_translator.h` — контракт преобразователя (целевые дополнения по разделу 7/8 дизайна; существующий заголовок — справочный контекст).
- `include/axis_motion_translator.h` — контракт транслятора движения оси + `src/axis_motion_translator.cpp` (планируемые изменения).
- Использует: `include/parameter_storage.h`, `include/axis_settings.h`, `include/driver_interface.h`.

## Поведение (алгоритм «дельта → команды движения»)

1. Из хранилища берутся целевое и текущее значения (в физических единицах).
2. `delta = target − current`.
3. Если `|delta| < epsilon` — движения не требуется, команда не формируется.
4. Перевод дельты в команды привода:
   - направление — знак дельты;
   - величина (обороты) — по масштабу «оборотов на градус» (`revs_per_degree`);
   - **скорость — считывается из хранилища в момент старта движения** и включается в команду старта (FR-10; решение владельца R-1).
5. Команда нормируется в `DriverCommand` и передаётся в `driver_interface` (`sendCommand`), которая ставит её в очередь (не блокирует).
6. `tick()` отслеживает движение: `is_moving()` драйвера, завершение (после чего цель фиксируется как текущая — `commit_target`), таймауты и аварийная остановка.

**Re-targeting**: если во время движения приходит новый целевой угол, `setTargetAngle` обновляет цель немедленно; транслятор пересчитывает нормированное действие для драйвера, FIFO целей не создаётся (FR-9, AC-5). Реализация перенацеливания — задача T5 [base-tasks.md](../sessions/base/artifacts/base-tasks.md).

## Кэш настроек оси

- Настройки (скорость 0x6000, масштаб 0x6002) берутся из **локального кэша** транслятора, а не из хранилища при каждом движении.
- Кэш обновляется по уведомлению `on_settings_changed` от хранилища настроек (дизайн, раздел 2.3 README и раздел 9): настройки применяются редко, поэтому дешевле обновлять кэш по событию, а не читать каждый цикл.
- Это же уведомление — точка, где при изменении скорости вычисляется, на какие будущие старты повлияет новое значение.

## Принципы (из артефактов аналитика)

- **Физическая логика отделена от транспорта** (README, раздел 2.4): транслятор работает с логическими командами движения; различия транспорта и модели привода инкапсулированы в реализациях `driver_interface`. Это исключает «взрыв комбинаторики» (параметр × драйвер × транспорт).
- **Скорость задаётся до старта** (дизайн, раздел 5): команд смены скорости в ходе движения не существует.
- **Свежие данные** (раздел 10, п.1): нет очереди целей, только перенацеливание.
- **Хранилище — единственное место между проходами**: транслятор не хранит целевые значения, только кэш настроек и состояние движения.

## Связи

- Вызывает: `driver_interface::sendCommand` (команды движения); `parameter_storage::read/target_units/current_units` (дельта); `axis_settings::rpm()/revs_per_degree()` (кэш настроек).
- Вызывается из: `parameter_storage`/роутер (уведомление об изменении), `src/main.cpp::loop()` (`tick()`).
