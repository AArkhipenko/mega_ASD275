Открой новую рабочую сессию для проекта mega_ASD275.

Формат вызова: `/start <id-сессии> <описание задачи>`
Пример: `/start fix-distance Реализовать хранилище расстояния и его транслятор`

$ARGUMENTS

## Шаг 1. Определи id и задачу

- id — транслит/латиница, нижний регистр, дефисы вместо пробелов (из первого слова аргумента). Если id занят (папка `docs/sessions/<id>` существует) — добавь суффикс `-2`, `-3` и т.д.
- задача — остаток аргументов после id.

## Шаг 2. Создай структуру сессии

Создай папки и файлы:

```
docs/sessions/<id>/
  session.md          — манифест сессии (шаблон ниже)
  project.md          — компактная справка о проекте (скопируй дословно из блока ниже)
  orchestrator-brief.md
  analytics-brief.md
  develop-brief.md
  review-brief.md
  artifacts/          — сюда аналитик складывает <id>-*.md
  reviews/            — сюда ревьюер складывает <id>-review.md
```

### session.md

```markdown
# Сессия <id>

- Дата: <сегодняшняя дата>
- Статус: открыта
- Задача: <описание задачи>

## Статус этапов

- [ ] 1. Аналитика (`analytics`) — артефакты в `artifacts/`
- [ ] 2. Разработка (`develop`) — код по `artifacts/<id>-*.md`
- [ ] 3. Ревью (`review`) — отчёт в `reviews/<id>-review.md`

## Файлы сессии

- `project.md` — компактная справка о проекте (общая для всех агентов)
- `orchestrator-brief.md` — правила оркестратора
- `analytics-brief.md` — правила этапа 1 (аналитика)
- `develop-brief.md` — правила этапа 2 (разработка)
- `review-brief.md` — правила этапа 3 (ревью)
```

### project.md (скопируй дословно)

```markdown
# mega_ASD275 — компактная справка

- Платформа: Arduino Mega 2560 (ATmega2560), фреймворк Arduino, сборка PlatformIO. Проверка сборки: `pio run`. Перед завершением работы обязательна успешная сборка.
- Симуляторы включаются флагами в `platformio.ini`: `USE_DWIN_LCM_SIMULATOR` (ввод `адрес значение` из Serial), `USE_SERVO_SIMULATOR` (имитация привода).
- Целевая архитектура (цепочка вызовов, интерфейсы в `include/`): `data_source` → `parameter_router` → `parameter_registry` → `parameter_storage` → `parameter_translator` → `driver_interface`.
- Ключевые файлы: `src/main.cpp` (композиция модулей и главный цикл); `include/` — интерфейсы и хранилища (`data_source.h`, `parameter_storage.h`, `parameter_translator.h`, `driver_interface.h`, `parameter_addresses.h`, `parameter_registry.h`, `parameter_router.h`, `axis_settings.h`, `axis_motion_translator.h`, `scaled_parameter.h`); `lib/` — реализации (`dwin_lcm`, `dwin_lcm_simulator`, `servo_driver`, `servo_simulator`).
- Адреса VP (DWIN): `0x5002` угол станины (0.01°), `0x5004` расстояние до упора (0.01 мм), `0x6000` скорость привода (об/мин), `0x6002` масштаб «обороты на градус», `0x6004` Modbus-адрес. Масштаб хранится в описании параметра, формула: физическая = сырое × масштаб.
- Стиль кода: C++ для AVR/Arduino, комментарии и строковые сообщения на русском, без новых предупреждений при `-Wall -Wextra`.
- Глобальная документация: `README.md` (целевая архитектура, блок-схемы, таблица адресов) — читать только если в брифе не хватает контекста.
```

### Брифы агентов

**orchestrator-brief.md**:

```markdown
# Роль: оркестратор (управление сессией)

- Читает: `session.md`, `project.md`.
- Не пишет код и не готовит артефакты сам.
- Управляет этапами через Task tool (субагенты): `analytics` → `develop` → `review`.
- Перед каждым этапом проверяет его вход: для develop — наличие `artifacts/<id>-*.md`, для review — изменённые файлы и артефакты.
- Показывает пользователю результат этапа и спрашивает явное согласие перед переходом (кроме итераций ревью→разработка).
- Verdict `changes-required` → вызвать `develop` для исправлений и повторить `review` (до 3 итераций).
- По завершении обновляет статусы в `session.md` и выдаёт итоговый отчёт.
```

**analytics-brief.md**:

```markdown
# Роль: аналитика (этап 1)

- Вход: `session.md`, `project.md`; при нехватке контекста — `README.md`, `docs/`, код в `src/ include/ lib/`.
- Выход (markdown, русский): `artifacts/<id>-requirements.md` (цель, границы, требования, ограничения платформы), `artifacts/<id>-design.md` (встраивание в архитектуру, список файлов, сигнатуры, адреса/масштабы), `artifacts/<id>-tasks.md` (план задач с зависимостями), `artifacts/<id>-acceptance.md` (критерии приёмки, сценарии, включая `pio run`).
- Описывай принципы работы, которые не видны из кода (почему так, ограничения, намерения) — их использует `/docs`.
- Запрещено: писать или править код (`src/`, `include/`, `lib/`).
- После создания артефактов отметь статус в `session.md` и верни список файлов.
```

**develop-brief.md**:

```markdown
# Роль: разработка (этап 2)

- Вход: `session.md`, `project.md`, `artifacts/<id>-*.md`. Если артефактов нет — остановись и попроси этап «Аналитика».
- Выход: изменения в `src/`, `include/`, `lib/`, `platformio.ini` по артефактам; обязательна успешная сборка `pio run` без новых предупреждений.
- Соблюдай целевую архитектуру из `project.md`; комментарии и строки — на русском; не выходи за рамки задачи из артефактов.
- По завершении отметь статус в `session.md` и отчитайся: файлы, статус сборки, что намеренно не делалось.
```

**review-brief.md**:

```markdown
# Роль: ревью (этап 3)

- Вход: `session.md`, `project.md`, `artifacts/<id>-*.md`, изменённый код (см. отчёт разработчика).
- Проверка: соответствие артефактам и критериям приёмки; архитектура; переполнения/деление на ноль, неблокирующий цикл; сборка `pio run`; стиль.
- Выход (markdown, русский): `reviews/<id>-review.md` — вердикт `approved` / `changes-required`, замечания с приоритетом (критично/желательно/низкий), для каждого — файл, строки, суть, предложение.
- Запрещено: править код.
- По завершении отметь статус в `session.md` и верни вердикт.
```

## Шаг 3. Завершение

- Запиши указатель текущей сессии: создай/обнови `docs/sessions/current.md` со строкой `session: <id>`. Это нужно, чтобы оркестратор знал, в какой сессии работать при последующих промтах (команда `/ask`).
- Покажи пользователю созданную структуру (`docs/sessions/<id>/`) и объясни режим работы: теперь он может писать промты команdeй `/ask <запрос>` (или выбрать агента `orchestrator` и писать промты напрямую) — оркестратор сам определит, какому агенту отдать запрос.
