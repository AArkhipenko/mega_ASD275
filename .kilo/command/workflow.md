Запусти workflow «аналитика → разработка → ревью → документация» для проекта mega_ASD275, управляя этапами как оркестратор.

$ARGUMENTS

## Определение сессии

- Если первый аргумент — это id существующей сессии (папка `docs/sessions/<id>`), работай в ней.
- Если id не передан — прочитай указатель `docs/sessions/current.md` (строка `session: <id>`); если там есть существующая сессия, работай в ней.
- Если сессии нет — сообщи, что нужно сначала создать её (`/session <id> <задача>`), и остановись.

## В рамках сессии

Прочитай `docs/sessions/<id>/session.md` и `docs/sessions/<id>/orchestrator-brief.md`, затем прогони этапы через субагентов:
- `analytics` — артефакты в `docs/sessions/<id>/artifacts/`;
- `develop` — код по артефактам + `pio run`;
- `review` — отчёт в `docs/sessions/<id>/reviews/`;
- `docs` — после вердикта `approved` перегенерируй `docs/generated/`.

Обновляй статусы в `session.md`. При вердикте `changes-required` возвращайся на разработку и повторяй ревью (до 3 итераций). В конце — итоговый отчёт: артефакты, изменённые файлы, вердикт, статус `pio run`, статус обновления `docs/generated/`.
