Запусти workflow «аналитика → разработка → ревью → документация» для проекта mega_ASD275, управляя этапами как оркестратор.

$ARGUMENTS

## В рамках сессии (если передан id сессии)

Если первый аргумент — это id существующей сессии (папка `docs/sessions/<id>`):
- прочитай `docs/sessions/<id>/session.md` и `docs/sessions/<id>/orchestrator-brief.md`;
- прогони этапы через субагентов `analytics`, `develop`, `review` строго по брифу сессии;
- артефакты, код и отчёты — в рамках сессии (`docs/sessions/<id>/`);
- обновляй статусы в `session.md`.

## Разово (без сессии)

Если id сессии не передан: прогони этапы через субагентов `analytics` (артефакты в `docs/artifacts/`), `develop` (код + `pio run`), `review` (отчёт в `docs/reviews/`).

## Всегда после одобрения ревью

После вердикта `approved` (или после финальной итерации с исправлениями) **обязательно перегенерируй документацию**: вызови субагента `docs` с заданием обновить `docs/generated/` (модули, функциональность, поток данных, связи с исходниками). Документация должна отражать изменения логики, внесённые на этапе разработки.

## Порядок и условия

- Проверяй наличие артефактов перед каждым этапом.
- При вердикте `changes-required` возвращайся на разработку и повторяй ревью (до 3 итераций).
- В конце — итоговый отчёт: артефакты, изменённые файлы, вердикт, статус `pio run`, статус обновления `docs/generated/`.
