# Лучшие практики написания кода (mega_ASD275)

## Архитектура

- **Все связи через интерфейсы** из `include/`: `data_source` → `parameter_router` → `parameter_registry` → `parameter_storage` → `parameter_translator` → `driver_interface`. Конкретика — только в реализации и composition root (`src/main.cpp`).
- Новый источник/драйвер/хранилище — новый класс в `include/**` (интерфейс уже есть) или в `lib/*/src/`. Не приклеивай логику к `main.cpp`, кроме сборки и цикла.
- Один системный параметр = один `parameter_translator`. Группа изменяемых вместе системных переменных — одно многоадресное хранилище с `owns()` / `address_at()` (пример: `axis_settings`).

## Масштабы и единицы

- Сырое значение × масштаб параметра → физическая величина. **Масштаб хранится в описании параметра**, а не магической константой в коде (`scaled_parameter` принимает `unit_scale`).
- Физику (delta → обороты/скорость) отделяй от транспорта (Modbus/RS111): транспорт скрыт за `driver_interface`.

## Границы и ошибки

- Контролируй диапазоны сырых значений (`set_raw_range`), тип `int32_t` для дельт, `uint16_t` для регистров; не полагайся на переполнение.
- Клэмп на границах протокола (пример: `±32767` оборотов в `start_move`).
- Признак успеха — `bool`, состояние ошибки — явное поле (`_comm_fault`), диагностика с префиксом подсистемы (`[DRV]`, `[SIM]`).
- Не используй исключения ОС; проверок на `0` перед делением/использованием — обязательно.

## Неблокируемость

- Всё, что связано с железом (ожидание ответа Modbus, движение), — неблокирующее или с явным таймаутом; ретраи ограничены (`MODBUS_MAX_RETRIES`).
- Главный цикл без `delay()`: состояние + `millis()`.

## Стиль и валидация

- Ключевые поля — с префиксом `_`, API — с документацией `/// @brief`.
- Комментарии и строки для человека — на русском, идентификаторы — английские.
- После любых изменений — `pio run` без новых предупреждений при `-Wall -Wextra`.
- Не добавляй код вне рамок задачи; несостыковки артефактов и кода — отдельным списком в отчёте.
